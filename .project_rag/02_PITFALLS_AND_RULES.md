# 02_PITFALLS_AND_RULES.md — Технические правила и решённые грабли

## Принципы взаимодействия и честности
1. **Никакой лести и ложных компромиссов:** Пользователь — Алексей, архитектор с 26-летним стажем и ML-инженер. Любая неточность или выдумка в угоду пользователю строго наказывается. Если данные неизвестны или сомнительны — ставить `______________` или явно указывать границы применимости.
2. **Точность ссылок на СП:** Использовать точные формулировки и ссылки на пункты СП 542.1325800.2024 (с Изм. № 1), СП 22.13330.2016, СП 20.13330.2016 и ГОСТ ISO 21898-2013.

## Решённые инженерные грабли (Pitfalls)

### 1. Касательная угла откоса $\alpha$ (поперечное сечение)
* **Грабли:** Измерение угла от земли ($y=0$) давало $\alpha \approx 56^\circ$ из-за вертикального бока первого яруса, что вызывало ложные предупреждения о превышении угла естественного откоса песка ($30^\circ\text{–}35^\circ$).
* **Решение:** Измерять касательную строго **от верхнего внешнего ребра 1-го яруса (опорной подошвы) до верхнего внешнего ребра гребня**: $\Delta H = (n_z - 1) h_{\text{факт}}$. Это физически отражает фактический угол скольжения ступеней ($38^\circ\text{–}47^\circ$).

### 2. Ложный складской лимит (`CHK_STACK_LIMIT`)
* **Грабли:** В исходном ТЗ стояло правило «при $V_{\text{ном}} > 1.5\text{ м}^3$ максимум 2 яруса, иначе `INVALID`». Это блокировало половину каталога (например, мешок $100\times 110\times 160$ см).
* **Причина:** Правило взято из ГОСТ ISO 21898-2013 для складского хранения в одиночный вертикальный столбик под 90°. В строительной трапеции под $45^\circ$ с перевязкой $b/2$ опрокидывание кинематически невозможно.
* **Решение:** Складской запрет снят. Введена физическая градация по распору грунта: до 4 ярусов — норма; 5 ярусов — предупреждение (`WARNING`); $>5$ ярусов — критический отказ (`INVALID`, риск разрыва полипропилена от $T > 20\text{ кН/м}$).

### 3. Проблема «мешка-чулка» (`CHK_UNDERFILLED_BAG`)
* **Грабли:** При засыпке песком мешок $160\text{ см}$ с БРН $1.3\text{ т}$ засыпается только на $76\text{ см}$ по высоте ($48\%$). Остальные $84\text{ см}$ ткани болтаются пустой складкой, сминаясь и вызывая осадку ярусов.
* **Решение:** Введена проверка степени заполнения по высоте ($h_{\text{факт}} / h_{\text{ном}} < 0.65 \to$ `WARNING`). Калькулятор рекомендует пропорциональные мешки меньшей высоты либо усиленную тару ($1.5\text{–}2.0\text{ т}$).

### 4. Обрезание блоков и наплыв текста на продольной развёртке
* **Грабли:** В SVG развёртки верхний ярус срезался границей viewBox, число рядов не всегда совпадало с сечением, а размерная подпись наезжала на нижний ряд мешков.
* **Решение:** Количество рядов строго равно `tiersCount`, чертёж центрирован по полю ($W=340$ при viewBox 440), торцы выровнены полублоками ($b/2$), сверху добавлен отступ $24\text{ px}$, размерная линия вынесена вниз под линию грунта с отступом $32\text{ px}$.

### 5. Сверхдлинное имя файла в Git на Windows
* **Грабли:** Файл `Техническое обоснование применения и расчётная методика...md` (>190 символов) вызывал ошибку Git `Filename too long` и блокировал автоматическую сборку в GitHub Actions / gh-pages.
* **Решение:** Включён `git config core.longpaths true`, файл переименован в компактный [SPECIFICATION_SP542.md](file:///d:/applications/BIG-BAG_CASTLE/SPECIFICATION_SP542.md).

### 6. Печать PDF на листах А4
* **Грабли:** По умолчанию браузер разрывал страницу посреди чертежей, оставляя Лист 1 полупустым, и печатал мусорные колонтитулы (URL, дата).
* **Решение:** В `@media print` Лист 1 плотно укомплектован чертежами и ведомостью, блок пояснительной записки принудительно переносится на Лист 2 (`break-before: page`), колонтитул ограничен `Лист X`.
